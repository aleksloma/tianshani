## მნიშვნელოვანი შენიშვნა

aura.ge-ზე გამოქვეყნებული ჭეიშვილის ტექსტი 1983 წლის ფილმის სცენარი არ არის — გვიანდელი, პოსტსაბჭოთა რედაქციაა (ბანკები, პოლიცია, პრივატიზაცია). პლატფორმისთვის **ფილმია კანონიკური**; `characters.json`-ში თითო პერსონაჟს აქვს `source` ველი (`film_and_book` / `film_only` / `book_mainly`). ლალისა და თენგიზის ზუსტი „საქმიანობა“ ვარაუდადაა მონიშნული (`confidence_note`).

## როგორ გამოვიყენოთ JSON LLM-თან

1. `world.setting_en` + `world.core_rules_en` + `world.shared_idiom_ka` — საერთო system context.
2. არჩეული პერსონაჟის `system_prompt_en`, `persona_ka`, `catchphrases_ka`, `excuse_repertoire_ka`.
3. 2–3 `sample_dialogues` few-shot მაგალითებად.
4. პასუხი ყოველთვის ქართულად, 1–3 წინადადება; ერთი ცნობილი ფრაზა მაქსიმუმ თითო პასუხში.
5. `redirects_to` — შემდეგი „კარი“, რომელსაც მოთამაშე უნდა მიაკაკუნოს.

## რაც აკლია

ფილმის ვიდეო/ტრანსკრიპტი ამ სესიიდან მიუწვდომელი იყო. სუბტიტრების დამატებით პერსონაჟთა ფრაზები და სცენები კიდევ დაზუსტდება.

## გაშვება და დეპლოი

ვებ-საიტი „დაბეჭდე ტიანშანი“ (Node.js + Express, ვანილა JS, Google Gemini, SQLite). დეტალები: `SETUP.md`, გადაწყვეტილებები: `DECISIONS.md`, ტესტები: `TEST_REPORT.md`.

### ლოკალურად

```bash
npm install
npm start
```

- საიტი: http://localhost:3000 · ადმინი: http://localhost:3000/admin
- პირველ გაშვებაზე იქმნება `settings.json` (`settings.example.json`-დან, შემთხვევითი ადმინის პაროლით — კონსოლში დაიბეჭდება). **Gemini-ს გასაღები** ჩაწერეთ `settings.json → gemini.api_key`-ში და გადატვირთეთ სერვერი. გასაღების გარეშე საიტი mock რეჟიმში მუშაობს (პასუხები მონაცემებიდან, LLM-ის გარეშე).
- `npm run dev` — nodemon-ით; `npm run test:all` — ყველა ტესტი (unit + API + Playwright E2E).

### ჰოსტინგზე (Render / Railway / Fly.io და სხვ.)

`settings.json` რეპოში არ არის — ჰოსტინგზე ყველაფერი გარემოს ცვლადებით:

| ცვლადი | სავალდებულო | რა არის |
|---|---|---|
| `GEMINI_API_KEY` | დიახ | Google AI Studio-ს გასაღები (გარეშე — mock რეჟიმი) |
| `ADMIN_PASSWORD` | დიახ | `/admin`-ის პაროლი (გარეშე ადმინი დაკეტილია) |
| `PORT` | ჰოსტინგი თავად აყენებს | პორტი; როცა `PORT` არსებობს, host ავტომატურად `0.0.0.0`-ა |
| `HOST` | არა | host-ის ხელით მითითება |
| `DB_PATH` | რეკომენდებული | SQLite ფაილის გზა persistent disk-ზე, მაგ. `/var/data/tianshani.db` |
| `GLOBAL_MONTHLY_USD` | არა | გამომცემლობის თვიური ბიუჯეტი დოლარებში (ნაგულისხმევი 50) |
| `PUBLIC_URL` | რეკომენდებული | საიტის საჯარო მისამართი (მაგ. `https://tianshani.example.ge`) — გაზიარების (Open Graph) ბმულებისთვის; არ არის — მოთხოვნის host-იდან ითვლება |

- **Build:** `npm ci` · **Start:** `npm start` · Node ≥ 20 (`package.json → engines`).
- სხვა პარამეტრები (ლიმიტები, მოდელი, შიდა კალენდარი: `game.start_date`, `game.days_per_season`, `game.days_per_chat_close`, `game.days_per_character_switch`, `game.days_per_exchange`) აიღება `settings.example.json`-იდან; შესაცვლელად ჰოსტინგზე შეგიძლიათ `settings.json` ფაილიც შექმნათ, ან `SETTINGS_PATH`-ით სხვა ფაილზე მიუთითოთ.
- **ბრაუზერის ლიმიტი:** `limits.per_client_input_tokens` და `per_client_output_tokens` — **500 000** თითო ბრაუზერზე თვეში (ზედა ზოლში ჩანს დახარჯული შემავალი ტოკენების %). უკვე დაგროვილი მთვლელები ინახება — ბრაუზერი, რომელმაც ამ თვეში 500 000-ზე მეტი დახარჯა, მაშინვე ლიმიტზეა.
- **შიდა დრო:** დრო მიდის მხოლოდ საუბრის დახურვისას — `game.days_per_chat_close` დღით (ნაგულისხმევი 20), თუ ამ საუბარში ერთი შეტყობინება მაინც გაიგზავნა; საუბრის შუაში თარიღი, სეზონი და ინტერტიტრი არ იცვლება. `game.days_per_exchange` და `game.days_per_character_switch` კონფიგურირებადია, ნაგულისხმევად 0.
- **ქართული კორექტურა (`gemini.proofread`, ნაგულისხმევად ჩართული):** პასუხის შემდეგ მეორე, იაფი გამოძახება ასწორებს მართლწერას/არარსებულ სიტყვებს; ~1–2 წამი და დაახლოებით ორმაგი გამომავალი ტოკენები. ადმინში — „შესწორებული პასუხები“.
- **ეგზემპლარები:** `game.seasons_per_lost_copy` (ნაგულისხმევი 1) — რამდენ სეზონში იკარგება ერთი ეგზემპლარი (2 — ორჯერ ნელა); დაკარგვისას კედელზე ფილმის საბაბიანი ფურცელი ჩნდება.
- **პასუხის სიგრძე:** `gemini.max_output_tokens` 180; `chat.trim_long_replies: true` — 3 წინადადებაზე გრძელი პასუხი სრულად ჩანს, მაგრამ ლოგში WARN-ად იწერება და ადმინში „ზედმეტად გრძელი პასუხები“ ითვლება.
- **გაზიარება:** `public/assets/og.jpg` (1200×630) და favicon-ები — `node scripts/make-og.mjs`, `node scripts/make-favicon.mjs`.
- **მობილური:** ტელეფონზე კედელზე 6 ჩარჩოა (`wall.characters_on_wall_mobile`), პლანშეტზე 9 (`wall.characters_on_wall_tablet`), დანარჩენები „ესაუბრე სხვას“ სიაშია.
- **გლობალური ბიუჯეტი (`budget`):** `global_monthly_usd` (ნაგულისხმევი 50), `price_input_per_1m_usd` 0.75, `price_output_per_1m_usd` 3.75, `warn_at_percent` 80. ყოველი მოთხოვნის წინ სერვერი ითვლის ამ თვის ხარჯს (UTC თვე) + მოსალოდნელ ხარჯს; თუ ბიუჯეტს გადააჭარბებს — ყველა ბრაუზერს 429 და მოდალი „ბიუჯეტში გარღვევა გვაქვს“. ადმინში — ბიუჯეტის ბარათი და „ბიუჯეტის განულება ამ თვისთვის“. **2027-01-01-დან Gemini-ს ფასი ორმაგდება** (1.50 / 7.50) — მაშინ ფასები `settings.json`-ში განაახლეთ. `0` ან უარყოფითი ბიუჯეტი ლიმიტს თიშავს (კონსოლში გაფრთხილებით).
- **კედლის ფონი ეტაპების მიხედვით:** `wall.background_by_stage` — 5 ელემენტი (ბზარის ეტაპები 0–4), თითო სურათის გზა `public/`-დან ან `null` (= წინა ეტაპის ფონი რჩება). ახალ ეტაპზე ფონი 1.5 წამში ნელა იცვლება. ახალი ფოტოს დასამატებლად ჩადეთ ფაილი `public/assets/`-ში და ჩაწერეთ გზა შესაბამის პოზიციაზე.
- **SQLite და ეფემერული დისკი:** Render/Railway/Fly-ის სტანდარტულ ინსტანსებზე ფაილური სისტემა ყოველ deploy-ზე/გადატვირთვაზე იშლება — `data/tianshani.db` (ლოგები, ტოკენების აღრიცხვა, ადმინის სესიები) დაიკარგება. ამიტომ მიაბით persistent disk/volume და `DB_PATH` მასზე მიუთითეთ (Render: Disk → `/var/data`, Railway: Volume, Fly: `fly volumes create` + mount).
- მაგალითი (Render Web Service): Runtime Node, Build `npm ci`, Start `npm start`, Environment: `GEMINI_API_KEY`, `ADMIN_PASSWORD`, `DB_PATH=/var/data/tianshani.db`, Disk mount path `/var/data`.
- `better-sqlite3` Linux-ზე prebuilt binary-ს იყენებს; build tools საჭირო არ არის.
